# Organization administration — T061

Organization administration manages colleges/departments inside existing institutions. A separate organization-administration grant delegates metadata management to a verified active account at an explicit institution or college root. It establishes that limited administrative authority without requiring a department membership. Only platform super admins issue, suspend, revoke or explicitly restore these grants; no legacy grant is promoted and delegates cannot redelegate. College scope includes its organization metadata and child departments, never their memberships, records, appointments or general audit.

New departments start closed to self-service requests. Closing requests does not reject existing requests or disable invitations while the department remains active. Archival requires no active role memberships and no active descendants; archived codes remain reserved. Archival revokes outstanding invitations and cancels delivery, preserves pending requests/history and blocks activation. Restore requires an active parent and leaves enrollment closed. All parent changes, institution creation, hard deletion and department transfers are deferred. Naming and retention policies still need institutional review; local names/codes are trimmed, non-empty, bounded strings with existing case-sensitive code uniqueness.

All writes require simulated staff MFA, recent authentication, CSRF, idempotency and a reason; edits require the current quoted revision. A transaction-wide write lock is shared with enrollment and SMTP delivery. Scope/state checks run in services and forced RLS/database guards under non-owner runtime roles. Account suspension also suspends organization grants; account reactivation does not restore them. Success audit is atomic, denials persist independently. Organization-only history exposes organization events/reasons, never student or invitation recipient content. Global reads require an operational purpose.

Administrative APIs live under `/api/v1/admin`: institutions (read only), org-units (list/create/detail/edit), org-units/{id}/enrollment, archive, restore and history. `/api/v1/organization-admin-grants` provides paginated own/global reads and super-admin-only creation/state transitions. Existing operational organization reads retain their boundary. `/me` adds independent administration capabilities, own grants and visible institution metadata epochs; it works with no operational department scopes. Metadata epochs invalidate list cursors/UI projections; permission epochs change on administration grant changes. Creating an organization never changes operational scope grants.
